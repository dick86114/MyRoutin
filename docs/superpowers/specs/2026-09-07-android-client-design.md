# MyToken Android 原生客户端设计

日期：2026-09-07
状态：设计已获用户确认，待书面审阅

## 1. 背景与目标

MyToken 是 macOS 菜单栏用量监控工具，用于直接调用多个大模型供应商的官方接口，展示用量、余额、剩余额度和重置时间。Android 客户端的目标是完整覆盖当前 macOS 已支持的供应商和核心能力，同时针对手机屏幕、触控交互和后台刷新进行原生适配。

Android 端不引入服务端，不建立账号系统，不把凭证上传云端。手机直接调用官方接口，配置在 Android 本地安全保存。Mac 到 Android 的配置迁移采用“二维码 + 局域网临时连接”，二维码只负责引导建立一次性迁移会话，配置包通过端到端加密的局域网连接传输。

目标平台：Android 10（API 29）及以上。

## 2. 产品定位与范围

Android 客户端是与 macOS 共享供应商能力和配置协议、但拥有独立移动端信息架构的原生客户端。两端共享供应商 ID、凭证类型、指标语义、错误分类、迁移协议和脱敏规则；两端不共享 UI、刷新调度、缓存、通知和平台专属设置。

首版完整覆盖当前 macOS 已支持能力：

- Routin
- DeepSeek
- GLM Coding Plan
- 火山方舟个人 Agent Plan
- 火山方舟 Coding Plan
- 多凭证管理、启用/停用、编辑、删除和连接测试
- 用量、余额、剩余额度和重置时间
- 5 小时和周用量维度
- 手机端独立排序和分组
- 手动刷新和自动刷新
- 50%、80% 和自定义阈值提醒
- Routin 官方签到
- Mac 到 Android 配置迁移
- 手动新增配置
- 本地安全存储和脱敏诊断

不迁移仅具有 macOS 意义的设置，例如菜单栏最多显示 4 个凭证、菜单栏指标样式、登录项设置、窗口尺寸和 macOS 菜单栏交互。菜单栏置顶凭证可以映射为 Android 的置顶凭证，但不限制手机首页只能显示 4 个。

## 3. 信息架构与交互

底部导航包含：首页、凭证、设置。

首页以 macOS 菜单栏弹窗为视觉和内容母版：保留供应商分组、凭证独立状态、用量/余额/剩余时间/重置时间的指标层级、状态颜色、进度条和供应商详情；将 Mac 的横向紧凑布局改为适合手机纵向滚动和触控的卡片布局。

首页结构：

- 顶部工具栏、整体刷新状态和最近更新时间
- 按供应商分组的凭证卡片
- 卡片内展示关键指标、进度条和状态
- 点击卡片进入详情页
- 下拉刷新全部凭证，支持单凭证刷新
- 供应商区块可折叠
- 失败时保留最近成功数据并标记过期

凭证卡片根据供应商能力显示字段：有额度上限时显示真实进度；只有余额接口时显示余额健康状态；没有的指标直接隐藏，不显示伪造的 0 或 100%。状态颜色必须配合文字标签，不能依赖颜色作为唯一信息来源。

凭证页负责按供应商分组、搜索、新增、编辑、启用/停用、删除、连接测试、拖动排序和导入预览。密钥默认掩码，保存前做格式校验，测试失败时仍允许保存但必须明确显示失败原因。

设置页包含刷新、通知、首页显示、数据迁移、安全与隐私、帮助与关于。Android 不显示菜单栏专属选项，而是提供置顶凭证、卡片密度、指标显隐和排序方式等移动端设置。

手机排序独立于 Mac 排序。首版默认支持全局手动排序和供应商分组后的组内排序，长按拖动完成调整；预留状态优先和最近更新时间排序。

Routin 签到位于对应凭证详情页，使用 Android Custom Tabs 打开官方页面。应用不读取或保存密码、验证码、Token、Cookie 或网页内容，结果以官方页面为准。

## 4. 跨平台配置协议

Mac 和 Android 使用独立、版本化的 MyToken Transfer Schema，不直接依赖 Swift 或 Kotlin 的序列化实现。协议必须包含 `schemaVersion`，供应商使用稳定字符串 ID，凭证类型明确表达，metadata 只允许白名单字段。

逻辑上配置包包含：

- 凭证 UUID、名称、供应商、凭证类型、启用状态和排序
- 供应商扩展 metadata
- 全局刷新设置、通知阈值等可迁移设置
- 对应的敏感凭证材料

传输前整个配置包统一加密。macOS 专属设置和 Android 专属设置不进入通用协议。未知字段应忽略；未知供应商应产生可理解的导入提示，不应静默伪造为其他供应商。

导入规则：保留原 UUID；相同 UUID 提示覆盖、跳过或创建副本；相同供应商和凭证后缀提示可能重复；用户取消时不写入任何数据；任一敏感字段解密或保存失败时整批回滚。

用量快照不作为正式迁移数据。可以携带带时间戳的临时快照用于首屏过渡，但 Android 首次导入后必须自行调用官方接口，不能把旧缓存显示为实时数据。

## 5. 二维码与局域网临时迁移

默认流程：

1. Mac 点击“迁移到 Android”。
2. Mac 创建一次性迁移会话、短时效连接口令和临时密钥对，并开启临时局域网服务。
3. Mac 显示二维码。
4. Android 扫码，读取协议版本、sessionId、局域网地址、端口、Mac 临时公钥、过期时间和连接口令。
5. Android 生成自己的临时密钥对，连接 Mac 临时服务并发送公钥及会话信息。
6. 双方使用 ECDH 派生迁移会话密钥。
7. Mac 使用 AEAD 加密配置包并发送。
8. Android 校验、解密并展示导入摘要。
9. 用户确认后写入 Android 安全存储。
10. 迁移完成或取消后双方销毁临时密钥和会话。

二维码不包含 API Key、Access Key、Secret Access Key、Bearer Token、Cookie、账号密码或完整用量数据。二维码只负责发现本次迁移会话。会话默认 5 分钟后失效，且只接受一个 Android 客户端，成功迁移后立即失效。

建议的密码学构件：X25519 密钥交换、HKDF-SHA256 密钥派生、AES-256-GCM 或 ChaCha20-Poly1305 数据加密、系统安全随机源和唯一 nonce。Android 必须校验二维码中的 Mac 临时公钥，Mac 必须校验会话 ID、连接口令和请求方向。

配置包发送前，Android 展示供应商数量、凭证数量和敏感项数量。用户确认前不写入本地存储。连接失败时提供重新生成二维码、检查局域网权限和取消入口；后续可增加双二维码纯离线备用模式，但默认流程是二维码加局域网。

## 6. Android 原生技术与模块

技术栈：Kotlin、Jetpack Compose、Material 3、Coroutines、Flow、ViewModel、Room、DataStore、Android Keystore、CameraX 或 ML Kit、WorkManager 和 Android Notifications。首版不使用常驻后台服务。

推荐工程目录：

```text
android/
├── app/
├── core/
├── data/
├── domain/
├── provider/
├── feature-home/
├── feature-credentials/
├── feature-settings/
└── feature-transfer/
```

`core` 放基础类型、时间格式化、错误分类、日志和加密接口；`domain` 放业务模型与用例；`data` 负责 Room、DataStore、Keystore、缓存和迁移包；`provider` 按 routin、deepseek、glm、volcengine 分模块实现请求、解析、签名和指标映射；各 feature 模块只负责对应 UI 和交互。

Android 各供应商适配器独立实现统一接口，不直接复用 Swift 源码：

```kotlin
interface UsageProvider {
    val providerId: ProviderId

    suspend fun fetchUsage(
        credential: Credential
    ): Result<UsageSnapshot>
}
```

跨平台复用通过协议文档、JSON fixtures、指标定义、签名样例和行为测试实现。

## 7. 本地数据安全

普通配置保存凭证 UUID、名称、供应商、凭证类型、排序、启用状态、metadata 和显示偏好。建议使用 Room；全局简单设置使用 DataStore。

敏感配置包括 API Key、Access Key、Secret Access Key 和 Bearer Token。Android 使用 Android Keystore 生成或保护设备密钥，将凭证密文保存到 Room 或专用文件；禁止将敏感字段存入明文 SharedPreferences、普通日志、剪贴板或诊断包。

macOS 侧在配合迁移功能前，应明确安全存储接口命名，区分普通 metadata 存储和 SecureCredentialStore。现有 `LocalKeyStore` 使用 UserDefaults 保存秘密材料，而 `KeychainSecretStore` 才使用 Keychain；后续应避免用容易误导的命名让迁移逻辑错误选择存储实现。

## 8. 状态、缓存与刷新

采用单向数据流：Repository → ViewModel StateFlow → Compose UI；用户操作经 ViewModel/UseCase 返回 Repository。每个凭证拥有独立的 Loading、Ready、Failed、Disabled 状态，单个请求失败不让首页整体空白。

前台支持打开页面刷新、下拉刷新、单凭证刷新和重复请求抑制。后台使用 WorkManager，允许系统调整实际执行时间；网络不可用时重试，低电量时减少请求。UI 区分刚刚更新、最近更新、数据较旧、数据已过期和从未成功刷新。

## 9. 测试与诊断

Mac 和 Android 使用相同的配置 JSON fixtures，覆盖各供应商、凭证类型、可选字段、未知字段、未知供应商、旧协议、空配置和重复 UUID。

迁移测试覆盖正常密钥交换、错误公钥、错误 sessionId、连接口令错误、会话过期、重放、篡改、nonce、断线、取消、回滚和重复导入。

供应商测试覆盖成功、空数据、过期数据、认证失败、限流、服务端错误、响应结构变化、指标映射和签名。

UI 测试覆盖多供应商首页、多凭证排序、余额型供应商、缺少重置时间、失败保留旧数据、深色模式、大字体、横竖屏、空状态、导入预览和删除确认。

诊断日志必须脱敏，禁止记录请求头、Authorization、Cookie、完整 URL 查询参数、密钥和网页登录内容。

## 10. 里程碑

### M1：Android 工程与跨平台协议

创建 Android 原生工程，完成 Android 10 基线、Compose/Room/WorkManager 基础结构、迁移协议、JSON fixtures 和手动添加凭证模型。

### M2：安全迁移

实现 macOS 临时迁移服务、二维码、Android 扫码、局域网连接、临时密钥交换、加密传输、Keystore 保存、导入预览和回滚。

### M3：首页与供应商

按 Mac 菜单栏弹窗设计实现 Android 首页，接入全部供应商，实现指标展示、错误状态、单凭证刷新和全量刷新。

### M4：凭证管理与排序

完成凭证编辑、删除、连接测试、长按排序、供应商分组、置顶和手机端独立排序设置。

### M5：后台刷新、通知和签到

完成 WorkManager、自动刷新、用量阈值通知、凭证失效通知和 Routin Custom Tabs 签到。

### M6：稳定性与发布

完成迁移压力测试、多设备测试、Android 版本测试、大字体/深色模式、网络异常、日志脱敏、发布构建和签名检查。

## 11. 验收标准

- Android 10 及以上设备可安装并运行原生 Compose 客户端。
- 首页在视觉层级和内容组织上与 macOS 菜单栏弹窗保持一致，同时适配手机纵向滚动。
- 当前 macOS 支持的全部供应商均可手动配置、导入、刷新和查看对应指标。
- Mac 生成二维码后，Android 只需扫码即可通过局域网完成一次性加密迁移。
- 二维码和日志不包含明文凭证。
- 迁移后的敏感凭证由 Android Keystore 保护。
- 手机端排序与 Mac 排序互不强制绑定。
- 单个供应商或凭证失败时，其他数据仍可正常展示。
- 后台刷新、阈值提醒、官方签到和设置页行为均有平台适配。
- 配置导入失败、取消、重复导入和会话过期均不会留下半套敏感数据。
