# 按凭证配置菜单栏指标与用量提醒设计

## 1. 背景

当前 MyToken 在通用设置中提供全局“用量维度”和全局通知阈值：

- 菜单栏维度只能在“5 小时”和“周”之间选择，并应用于所有凭证。
- 通知使用同一组低阈值和高阈值判断所有凭证。
- `AlertEvaluator` 同时处理旧版固定字段和新版标准化指标，仍依赖固定维度枚举及指标名称推断。

该模型只适合所有凭证拥有相同额度结构的早期单供应商场景。当前不同供应商、不同套餐实际可能提供 5 小时、周、月、Token 包、账户余额、状态和其他窗口指标，因此全局配置无法准确表达用户意图。

本设计取代 `2026-09-04-settings-redesign-design.md` 中“通用设置暂时保留显示维度和全局阈值”的决定。

## 2. 已确认的产品决策

1. 每个凭证在菜单栏中只显示一个指标。
2. 菜单栏指标选项根据该凭证实际可用的标准化指标动态生成。
3. 每个凭证默认使用“自动”指标，用户可以手动选择。
4. 通知保留一个全局总开关，具体规则按凭证和指标独立配置。
5. 每个凭证的提醒默认开启，用户可以手动关闭。
6. 新发现的可预警指标默认创建并启用提醒规则，提高功能可发现性。
7. 菜单栏指标配置放在“菜单栏管理”；提醒配置放在“凭证管理”；通用设置只保留通知总开关。

## 3. 目标

- 让菜单栏真正显示用户为单个凭证选择的指标。
- 支持供应商和套餐变化产生的不同指标集合，不在 UI 或核心设置中硬编码供应商名称。
- 让每条提醒规则与明确的凭证、指标和判断方向绑定。
- 为已有用户提供无损迁移，升级后继续获得提醒。
- 保持菜单栏单元宽度、排序和最多五项限制不变。
- 统一提醒评估入口，消除旧字段和标准化指标并行判断造成的重复或歧义。

## 4. 非目标

- 不允许一个凭证在菜单栏中同时显示多个指标。
- 不允许跨凭证合计额度或共享阈值。
- 不为没有可靠上限的普通数值伪造百分比。
- 不把提醒配置写入供应商鉴权 `metadata`。
- 不在本次设计中增加服务端同步、跨设备同步或团队策略。
- 不改变供应商 API 请求、凭证秘密存储和刷新间隔策略。

## 5. 方案选择

### 5.1 供应商和套餐硬编码

由应用维护“供应商 + 套餐类型 -> 可选维度”的固定映射。

优点是首次刷新前也能显示完整选项。缺点是套餐名称和接口能力变化后容易过期，同一套餐的不同账户也可能返回不同指标，因此不采用该方案作为事实来源。

### 5.2 每凭证一组固定枚举

把现有 `DisplayDimension` 移到每个凭证，但仍只支持 `fiveHour`、`weekly` 等固定枚举。

该方案改动较小，但无法覆盖余额、月度窗口和未来供应商指标，也无法可靠处理相同含义但不同 ID 的数据，因此不采用。

### 5.3 按标准化指标 ID 动态配置

以 `UsageSnapshot.normalizedMetrics` 为运行时事实来源，每个凭证保存一个稳定的菜单栏 `metricID`，提醒保存按 `metricID` 区分的规则。

该方案能够覆盖现有多供应商模型，并允许供应商新增指标而不修改全局枚举。本设计采用此方案。

## 6. 数据模型

### 6.1 凭证用量偏好

新增独立于 `KeyConfiguration.metadata` 的用户偏好模型：

```swift
struct CredentialUsagePreferences: Codable, Equatable, Sendable {
    var menuBarMetricID: String?
    var notificationsEnabled: Bool
    var alertRules: [MetricAlertRule]
}
```

- `menuBarMetricID == nil` 表示“自动”。
- `notificationsEnabled` 是凭证级提醒总开关，默认 `true`。
- `alertRules` 按指标 ID 保存用户已确认、修改或关闭的提醒规则。
- 该配置不决定凭证是否加入菜单栏，菜单栏成员和顺序仍由 `CredentialDisplayOrder` 管理。

### 6.2 指标提醒规则

```swift
enum MetricAlertValueSource: String, Codable, Sendable {
    case usedPercent
    case remainingPercent
    case absoluteValue
    case healthState
}

enum MetricAlertComparator: String, Codable, Sendable {
    case greaterThanOrEqual
    case lessThanOrEqual
    case becomesUnhealthy
}

struct MetricAlertThreshold: Codable, Equatable, Sendable {
    var level: AlertLevel
    var value: Decimal?
}

struct MetricAlertRule: Codable, Equatable, Identifiable, Sendable {
    var id: String
    var metricID: String
    var isEnabled: Bool
    var valueSource: MetricAlertValueSource
    var comparator: MetricAlertComparator
    var thresholds: [MetricAlertThreshold]
}
```

规则 ID 由凭证 ID、指标 ID 和规则类型稳定生成，不能使用显示标签生成。指标标签允许供应商修改或本地化，持久化匹配只使用 `metricID`。

### 6.3 持久化

`AppSettings` 新增版本化配置：

```text
credentialUsagePreferences.v1
```

底层使用 `[String: CredentialUsagePreferences]`，键为凭证 UUID 字符串，并通过 `JSONEncoder` 写入 `UserDefaults`。选择独立设置存储的原因：

- 这些字段是本机展示和通知偏好，不属于供应商鉴权信息。
- 编辑凭证秘密或供应商请求参数时不应覆盖用户的展示偏好。
- 删除凭证时可以独立清理设置、提醒去重状态和缓存。

### 6.4 指标语义

当前 `NormalizedUsageMetric` 通过标签是否包含“剩余”判断百分比方向，这不能作为新提醒系统的可靠依据。标准化指标需要增加显式语义：

```swift
enum NormalizedUsageMetricSemantic: String, Codable, Sendable {
    case usedQuota
    case remainingQuota
    case balance
    case status
    case value
}
```

每个供应商适配器在生成指标时必须填写语义。旧缓存缺少该字段时允许执行一次兼容推断，但推断结果只用于迁移，新的菜单栏解析和提醒规则不得继续依赖本地化标签文本。

## 7. 动态指标能力

### 7.1 事实来源

指标能力按以下优先级解析：

1. 最近一次成功快照的 `normalizedMetrics`。
2. 供应商适配器声明的预期指标描述，用于首次刷新前提供合理选项。
3. 没有快照和能力声明时只提供“自动”。

运行时快照始终高于供应商名称或用户填写的套餐提示，因为真实接口结果能够反映账户差异和套餐变更。

### 7.2 菜单栏兼容性

首期允许以下指标进入菜单栏选择器：

- `progress`：显示用量或剩余额度的百分比进度。
- `balance`：显示余额健康状态，不伪造百分比。
- `status`：显示账户可用性或连接状态。

普通 `value` 指标默认不进入菜单栏，因为当前固定宽度指标无法可靠表达任意数值。未来新增明确的数值菜单栏样式后再开放。

### 7.3 自动选择

“自动”按下列顺序选择：

1. 供应商适配器明确标记的首选菜单栏指标。
2. 第一个健康且有明确上限的 `progress` 指标。
3. 第一个 `balance` 指标。
4. 第一个 `status` 指标。
5. 没有兼容指标时显示未知状态。

同一快照内自动选择必须稳定，不能因字典枚举顺序改变。供应商生成的指标数组顺序和显式优先级共同决定结果。

用户手动选择的指标暂时消失时保留原 `metricID`，本次渲染回退到“自动”并在设置页标记“当前套餐不可用”。该指标重新出现后恢复用户选择。

## 8. 菜单栏管理

### 8.1 卡片配置

每张凭证排序卡片增加一个紧凑菜单控件：

```text
[拖拽] [指标图标] 别名 / 供应商 · 套餐   [菜单栏指标：自动⌄] [加入/移除]
```

- 菜单内容只列出该凭证当前兼容的指标。
- 未加入菜单栏的凭证也允许提前选择指标。
- 选择后预览和真实 `NSStatusItem` 立即使用新指标。
- 菜单栏预览和真实菜单栏共用同一指标解析器，不在视图中重复选择逻辑。

### 8.2 渲染接口

`MenuBarIndicatorModel.make` 不再接收全局 `DisplayDimension`，改为接收已经解析出的标准化指标：

```swift
static func make(
    state: KeyUsageState,
    descriptor: ProviderDescriptor,
    metric: NormalizedUsageMetric?
) -> MenuBarIndicatorModel
```

新增 `MenuBarMetricResolver` 负责：

- 读取凭证偏好。
- 匹配快照指标。
- 执行自动选择和失效回退。
- 返回用于菜单栏、预览和辅助功能标签的同一个指标。

## 9. 提醒配置

### 9.1 开关层级

提醒使用三个层级：

1. 系统通知权限：由 macOS 管理。
2. 应用通知总开关：保留在“通用”，默认开启。
3. 凭证和指标规则开关：位于单个凭证提醒设置中，默认开启。

任一上层关闭时不发送通知，但保留下层配置。重新开启后不补发关闭期间已经错过的历史提醒，只评估当前刷新窗口。

### 9.2 默认规则

首次发现可预警指标时，根据指标语义创建默认规则：

| 指标语义 | 默认条件 | 默认阈值 |
| --- | --- | --- |
| 已用百分比 | 大于等于 | 80%、95% |
| 剩余百分比 | 小于等于 | 20%、5% |
| 余额 | 低于供应商阈值或健康状态异常 | 供应商有可靠阈值时使用；否则仅严重状态 |
| 状态 | 变为不可用、认证失败或严重状态 | 无数值阈值 |
| 普通数值 | 默认不创建规则 | 无 |

新指标默认开启，但必须保留用户意图：

- 用户关闭过的同一指标规则再次出现时仍保持关闭。
- 用户关闭整个凭证提醒后，新指标可以创建规则，但不发送通知。
- 套餐切换导致指标暂时消失时规则进入休眠，不删除。
- 用户删除凭证时删除对应偏好和提醒去重状态。

### 9.3 凭证管理界面

凭证主列表继续保持紧凑，不直接展开全部阈值。每张凭证卡片增加通知按钮，打开独立设置弹窗或检查器：

```text
提醒此凭证                         [开关]

5 小时用量                        [开关]
已用达到                 80% / 95%

周用量                            [开关]
已用达到                 80% / 95%

账户余额                          [开关]
余额低于                         10 CNY
```

界面必须使用符合指标方向的文案，不再使用含义不明确的“低阈值”和“高阈值”。金额规则必须显示币种。

## 10. 提醒评估流程

刷新成功后的流程调整为：

```text
UsageProvider
  -> UsageSnapshot.normalizedMetrics
  -> CredentialUsagePreferencesResolver
  -> 只选择已启用且当前可计算的 MetricAlertRule
  -> AlertEvaluator
  -> 去重与窗口水位
  -> NotificationSender
```

`AlertEvaluator` 不再遍历旧版 `fiveHour`、`weekly`、`token` 字段后再次遍历 `metrics`。所有提醒统一通过 `normalizedMetrics` 和规则执行，避免重复通知和通过标签文本猜测指标类型。

判断规则：

- `usedPercent` 使用 `used / limit`。
- `remainingPercent` 优先使用 `remaining / limit`，不能用已用比例代替。
- `absoluteValue` 使用指标的 `value` 和币种。
- `healthState` 只在健康状态跨入配置的异常等级时触发。
- 无法计算、数据过期或字段缺失时不发送数值阈值提醒。
- 通知正文包含供应商、凭证别名、指标名称、当前值和重置时间，不包含秘密字段。

去重键从固定 `UsageDimension` 改为：

```text
credentialID + metricID + ruleID + windowIdentifier + thresholdLevel
```

这样相同供应商的多个凭证、同一凭证的多个指标和不同套餐窗口不会互相覆盖。

## 11. 通用设置调整

“通用”页面保留：

- 刷新间隔。
- 登录时启动。
- 启用通知总开关。

从通用页面移除：

- 全局用量维度。
- 全局低阈值。
- 全局高阈值。

移除 UI 不代表立即删除旧持久化键。旧键至少保留一个兼容版本，用于迁移和旧版本回滚。

## 12. 迁移策略

### 12.1 菜单栏维度

首次创建凭证偏好时：

1. 如果旧全局维度是 `fiveHour`，且该凭证存在 `fiveHour` 指标，保存该指标 ID。
2. 如果旧全局维度是 `weekly`，且该凭证存在 `weekly` 指标，保存该指标 ID。
3. 无对应指标时保存 `nil`，使用“自动”。
4. 迁移必须等待该凭证拥有快照或供应商能力描述，不能凭供应商名称猜测。

### 12.2 通知规则

首次发现指标且没有凭证规则时：

1. 凭证提醒默认开启。
2. 已用百分比规则继承旧全局 80% / 95% 或用户修改后的阈值。
3. 剩余百分比规则将首次提醒设为 `100 - low`，严重提醒设为 `100 - high`；默认 80% / 95% 对应剩余 20% / 5%。
4. 余额和状态按默认规则生成。
5. 完成迁移后写入版本标记，避免每次启动覆盖用户修改。

全局 `notificationsEnabled` 原值直接保留，不强制重新开启用户主动关闭的应用总开关。“默认开启”只适用于新安装和此前没有明确关闭记录的用户。

## 13. 异常和边界情况

- 首次刷新失败：菜单栏指标选择器只显示“自动”，原手动选择仍保留。
- 指标 ID 改名：视为新指标，旧规则休眠；供应商适配器需要提供显式迁移映射才能继承。
- 套餐变化：重新计算选项，新指标创建默认提醒，旧指标规则保留但休眠。
- 凭证停用：不刷新、不提醒，但保留菜单栏指标和提醒配置。
- 凭证移出菜单栏：不影响该凭证提醒。
- 凭证删除：删除偏好、提醒去重状态和相关缓存。
- 无上限指标：不得创建百分比提醒。
- 余额币种变化：原金额阈值停止执行并提示用户重新确认，不能跨币种直接比较。
- 供应商同时返回旧字段和标准化指标：只使用 `normalizedMetrics` 评估一次。

## 14. 测试策略

### 14.1 数据模型

- 凭证偏好编码、解码和版本迁移。
- UUID 键清理和未知字段向前兼容。
- 用户关闭的规则在指标消失并恢复后仍保持关闭。
- 新增指标默认生成开启规则。

### 14.2 菜单栏解析

- 每个凭证选择不同指标时分别渲染正确指标。
- “自动”选择遵循稳定优先级。
- 手动指标失效时回退，恢复后重新采用原选择。
- `value` 指标不会出现在首期菜单栏选项中。
- 设置预览和真实菜单栏使用相同解析结果。

### 14.3 提醒

- 已用百分比按 80% / 95% 正向触发。
- 剩余百分比按 20% / 5% 反向触发。
- 余额规则按正确币种和绝对值触发。
- 状态规则只在状态跨入异常等级时触发。
- 全局、凭证或指标任一开关关闭时不发送。
- 同一窗口和同一阈值不重复发送。
- 不同凭证、指标和规则的去重键互不干扰。
- 旧字段与标准化指标并存时不重复通知。

### 14.4 界面

- 通用页面不再显示全局维度和全局阈值。
- 菜单栏管理中每张凭证只显示一个指标选择器。
- 凭证提醒检查器只展示当前可预警指标。
- 无快照、套餐变化、币种变化和休眠规则均有明确状态。
- 键盘、VoiceOver 和减弱动态效果模式可完成全部设置。

## 15. 实施顺序

1. 新增凭证用量偏好模型、存储和迁移。
2. 引入动态指标能力解析与 `MenuBarMetricResolver`。
3. 将菜单栏和设置预览切换到每凭证单指标。
4. 在菜单栏管理卡片加入指标选择器，移除通用维度 UI。
5. 将提醒评估统一到 `normalizedMetrics + MetricAlertRule`。
6. 在凭证管理中加入凭证级和指标级提醒设置。
7. 移除通用阈值 UI，保留旧键兼容读取。
8. 完成数据、通知、界面和真实菜单栏回归验证。
