# Mac → Android 迁移故障排查

迁移通过局域网直连完成：Mac 发起迁移并展示二维码，Android 扫码后与 Mac 建立
TCP 连接，经 X25519 + HKDF + AES-256-GCM 端到端加密后一次性发送凭证包。
密钥只在密文内传输，Mac 不会保存副本，服务器不经手任何数据。

## 迁移前置条件

1. **同一局域网**：两台设备必须连接同一网络（推荐同一 Wi-Fi）。Mac 端展示的
   二维码内含 Mac 的局域网 IP；跨网段、AP 隔离或访客网络都会导致连不上。
2. **Mac 端版本**：使用包含"迁移到 Android"入口的 MyToken 版本（设置 → 凭证
   管理 → 迁移到 Android）。
3. **Android 端**：Android 10+，已安装 MyToken，并在凭证页或设置页选择
   "从 Mac 导入"，授予相机权限（仅用于扫码）。
4. **二维码有效期**：会话 5 分钟后过期；过期后需在 Mac 端重新发起迁移。

## 常见失败与处理

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 扫码后一直"连接中…" | 不在同一网段 / AP 隔离 / Mac 防火墙拦截 | 确认两设备连接同一路由器；关闭 Wi-Fi 访客隔离；系统设置 → 网络 → 防火墙允许 MyToken 入站连接 |
| "二维码已过期" | 会话超过 5 分钟 | 在 Mac 端重新发起迁移，重新扫码 |
| "连接码校验失败" | 扫到旧会话的二维码 | 关闭 Android 扫码页重新进入，使用最新二维码 |
| 解密失败 / 数据被篡改提示 | 密文被篡改或网络中间设备干扰 | 重新发起迁移；更换网络后重试 |
| 导入预览显示"无密钥" | Mac 上该凭证的密钥不可读（或配置后未保存密钥） | 在 Mac 端打开该凭证确认密钥可刷新用量，再重新迁移 |
| 导入计数出现"跳过 N 条无密钥" | 同上；Android 不会写入空密钥 | 补全 Mac 端密钥后重新迁移，或在 Android 端手动添加 |
| 导入中途失败提示已回滚 | 设备存储异常或 Keystore 错误 | 清理存储空间后重试；被覆盖的凭证会自动恢复原值 |
| 重复导入 | 同一凭证重复迁移 | 预览页选择"跳过重复"（保留本机）或"覆盖重复"（以 Mac 为准） |

## 迁移安全说明

- 二维码包含一次性 X25519 临时公钥、连接码和会话过期时间；会话一次性，
  发送完成后即销毁密钥材料。
- 整个凭证包（含密钥字段，均为 base64url 词法编码）由会话密钥 AES-256-GCM
  加密后发送，AAD 绑定协议版本与会话 ID，跨会话重放无效。
- Android 端密钥落盘前经 Android Keystore 包裹加密（AES-256-GCM），密文保存在
  `noBackupFilesDir`，不进入云备份；诊断日志不包含凭证材料。
- 若多次迁移失败且以上步骤无效，请在两端分别退出迁移页面后重新开始，并确认
  MyToken 为最新版本。
