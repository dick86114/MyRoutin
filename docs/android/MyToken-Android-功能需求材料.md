# MyToken Android 客户端功能需求材料

## 1. 产品定位

MyToken 是一个本地优先的多模型用量监控工具。Android 客户端用于在手机上查看和管理多个大模型服务凭证，展示用量、额度、余额、消耗趋势与重置时间，并支持从 macOS 客户端安全迁移配置。

客户端不提供云端账号系统，不将用户凭证上传到第三方服务；凭证和本地偏好应保存在用户设备上，敏感信息必须经过系统安全机制保护。

## 2. 目标用户

- 同时使用多个大模型服务或中转服务的开发者。
- 需要在移动场景中检查额度、余额和重置时间的团队负责人。
- 希望在手机上继续使用 macOS 端已有配置的个人用户。

## 3. 核心功能

### 3.1 凭证管理

应用应支持管理以下类型的凭证：

- Bearer Token / API Key。
- 独立 API Key。
- Access Key ID 与 Secret Access Key 组合。

用户应能够：

- 手动添加凭证。
- 编辑凭证名称、密钥、接口地址、用户 ID、区域、官网地址等元数据。
- 启用或停用凭证。
- 删除凭证，并在删除前确认影响范围。
- 调整凭证展示顺序。
- 对单个凭证执行连接测试，并查看成功或失败结果。

### 3.2 供应商支持

Android 客户端应覆盖以下供应商能力：

- Routin：订阅周期用量、Token 包用量、订阅起止时间、重置时间。
- DeepSeek：账户余额、赠金余额、充值余额、账户可用状态。
- 智谱 GLM Coding Plan：5 小时用量、每周用量、模型调用量、MCP 调用量。
- 火山方舟：个人 Agent Plan 或 Coding Plan 的近 5 小时、近一周、近一月用量及重置时间。
- New API：账户额度、已用额度、剩余额度、今日/近 24 小时/近 7 天/近 30 天 Token 消耗、消费金额、RPM、TPM、累计请求数。

供应商适配应统一处理认证方式、接口地址、区域、计划类型、错误码、限流、认证失败、响应解析失败和网络失败。

### 3.3 用量展示

用量页应呈现每个启用凭证的主要数据：

- 凭证别名。
- 供应商和套餐信息。
- 已用量、总量、剩余量。
- 百分比或余额。
- 重置时间。
- 距离重置的剩余时长。
- 最近成功刷新时间或刷新状态。

不同供应商的指标语义不同，不应将Token、货币、请求次数或账户状态混用为同一种数据类型。应用应按供应商和指标类型选择合适的展示语义，并保留足够精度。

### 3.4 刷新能力

应用应支持：

- 打开应用时自动恢复上次成功数据。
- 进入首页后刷新启用凭证。
- 手动刷新全部凭证。
- 单独刷新某个凭证。
- 下拉刷新。
- 自动刷新周期设置。
- 仅在 Wi-Fi 下刷新。
- 打开应用时刷新。
- 失败后自动重试。
- 刷新过程中的状态反馈。
- 失败原因展示和单凭证重试。

刷新结果应缓存，应用重启后可展示上次成功数据，并明确标识数据可能已过期。

### 3.5 阈值提醒

应用应支持用量提醒：

- 全局启用或禁用提醒。
- 设置低阈值和高阈值。
- 设置凭证失效提醒。
- 用量超过阈值时通知用户。
- 余额异常或凭证不可用时通知用户。
- 同一刷新周期内避免重复打扰。
- Android 13 及以上请求通知权限，未授权时静默降级并在设置中说明状态。

通知内容不得包含密钥、Cookie、完整请求头或其他敏感凭证材料。

### 3.6 数据迁移

用户应能够从 macOS 客户端迁移配置到 Android：

- macOS 发起一次性迁移会话并展示二维码。
- Android 扫描二维码。
- 两台设备在同一局域网内建立直连。
- 配置包使用端到端加密传输。
- Android 解析后展示导入预览。
- 用户可选择跳过重复项或覆盖重复项。
- 导入完成后展示新增、覆盖、跳过和无密钥跳过数量。

迁移会话应具备过期时间、单次使用、取消即销毁等约束。二维码和诊断日志不得包含明文密钥。

### 3.7 安全与隐私

应用应满足：

- 密钥保存在设备本地安全存储中。
- 敏感文件不进入云备份或设备迁移备份。
- 日志、错误提示和测试报告不包含完整密钥。
- 相机权限仅用于扫描迁移二维码。
- 通知权限仅用于用量提醒。
- 网络请求仅用于供应商 API、迁移连接和更新检查所需地址。

## 4. 页面与信息需求

### 4.1 首页

首页用于快速查看所有启用凭证的当前状态。

页面应包含：

- 账户总量概览，例如当前可见凭证数量。
- 最近一次成功刷新时间。
- 按供应商筛选的能力。
- 每个启用凭证的关键用量信息。
- 加载、空状态、刷新中、失败和已过期状态。
- 进入凭证详情的方式。
- 手动添加凭证入口。
- 从 Mac 导入入口。

停用凭证不应出现在首页结果中。

### 4.2 凭证列表

凭证列表用于管理全部本机凭证。

页面应支持：

- 查看凭证别名、供应商和凭证类型。
- 启用或停用凭证。
- 调整凭证顺序。
- 进入编辑页。
- 删除凭证。
- 从 Mac 导入。
- 手动添加凭证。
- 空状态引导。

列表应反映 Android 本地排序，不应依赖或覆盖 macOS 端顺序。

### 4.3 凭证详情

详情页用于查看单个凭证完整数据。

页面应包含：

- 凭证名称。
- 供应商与套餐。
- 凭证类型。
- 最近刷新时间。
- 刷新状态或错误原因。
- 全部可用指标，而不是只显示摘要指标。
- 刷新操作。
- 编辑入口。
- 删除入口。
- Routin 凭证的签到入口。

### 4.4 添加 / 编辑凭证

添加和编辑页用于创建或修改本机凭证。

页面应根据供应商动态显示：

- 凭证名称。
- Bearer Token 或 API Key。
- Access Key ID 与 Secret Access Key。
- 区域。
- 接口地址。
- 用户 ID。
- 官网地址。

页面应提供：

- 密钥显示与隐藏。
- 保存。
- 连接测试。
- 测试成功或失败反馈。
- 校验错误提示。
- 编辑已有凭证时保留原有启用状态和本地标识。

### 4.5 设置

设置页用于管理本地偏好。

应包含：

- 主题模式：跟随系统、浅色、深色。
- 自动刷新开关。
- 刷新频率。
- 仅 Wi-Fi 下刷新。
- 打开应用时刷新。
- 失败后自动重试。
- 用量提醒开关。
- 低阈值和高阈值。
- 凭证失效提醒。
- 系统通知权限状态和授权入口。
- 数据迁移入口。
- 应用版本和本地存储说明。

### 4.6 迁移流程

迁移流程包括扫码、连接、解密、预览和确认导入。

应展示：

- 当前连接阶段。
- 相机权限不足状态。
- 二维码无效或过期状态。
- 网络不可达状态。
- 导入摘要：供应商数量、凭证数量、敏感项数量。

### 4.7 桌面小组件

应用应提供单凭证桌面小组件。

应包含：

- 添加小组件时选择一个已启用凭证。
- 后续支持从小组件更换所选凭证。
- 展示所选凭证的关键用量信息。
- 展示数据更新状态或最后更新时间。
- 复用应用的后台自动刷新设置和调度能力。
- 支持通过小组件按钮立即刷新。
- 所选凭证被删除或不可用时展示引导状态。
- 小组件只展示用量、余额、额度、状态等概览信息，不展示凭证机密。
- 每个待导入凭证的名称、供应商、类型、是否包含密钥、是否与本机重复。
- 跳过重复或覆盖重复操作。
- 导入完成统计。
- 取消或返回入口。

### 4.7 状态与异常

每个页面都应定义：

- 首次加载。
- 空数据。
- 加载中。
- 网络失败。
- 认证失败。
- 限流。
- 服务不可用。
- 响应解析失败。
- 本地存储失败。
- 权限拒绝。
- 二维码或迁移会话过期。

错误应帮助用户判断下一步操作，例如重试、检查网络、检查凭证、重新授权或重新发起迁移。

## 5. 非功能需求

- 支持 Android 10 及以上。
- 敏感凭证使用系统安全存储保护。
- 本地数据库、DataStore 和密文文件不参与云备份。
- 网络请求需要连接、读取和整体超时保护。
- 单凭证失败不应阻断其他凭证刷新。
- 同一凭证不应并发重复刷新。
- 刷新并发数量应有上限。
- 应用更新或重启后，缓存快照和加密密钥仍可读取。
- 诊断输出必须脱敏。
- 不引入云端账号、远端配置同步或第三方遥测。

## 6. 验收标准

1. 用户可以手动添加、编辑、启用、停用、删除和排序凭证。
2. 用户可以从 macOS 完成一次加密迁移，并在 Android 端成功导入凭证。
3. 所有声明支持的供应商都能展示对应指标并完成刷新。
4. New API 能展示账户额度、Token 消耗、消费金额、RPM、TPM 和累计请求。
5. 首页只展示启用凭证。
6. 刷新失败时保留上次成功数据，并提示失败原因或过期状态。
7. 用户可以设置刷新频率、网络条件、重试、提醒阈值和主题模式。
8. 卡片密度设置能改变首页信息密度。
9. 应用重启后凭证、密钥、排序、缓存和偏好设置仍然可用。
10. 删除凭证后，本地排序和关联缓存同步清理。
11. 诊断和日志中无法找到明文密钥或完整凭证材料。
12. Android 13 以上未授权通知时，应用仍可正常查看用量，只是无法发送提醒。
